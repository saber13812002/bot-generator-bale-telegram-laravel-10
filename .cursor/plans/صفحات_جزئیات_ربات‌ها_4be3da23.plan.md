# ساخت صفحات جزئیات ربات‌ها

## هدف

ایجاد صفحات زیبا و قابل ویرایش برای هر ربات که شامل توضیحات کامل، عکس، ویژگی‌ها و ربات‌های مرتبط باشد.

## ساختار دیتابیس

### 1. Migration: اضافه کردن فیلدهای جدید به `webhook_endpoints`

فایل: `database/migrations/YYYY_MM_DD_HHMMSS_add_details_to_webhook_endpoints_table.php`

فیلدهای جدید:

- `detailed_description` (text, nullable) - توضیحات کامل و جامع
- `image_path` (string, nullable) - مسیر عکس در storage/public
- `image_url` (string, nullable) - URL خارجی عکس
- `features` (json, nullable) - لیست ویژگی‌ها به صورت JSON
- `usage_instructions` (text, nullable) - دستورالعمل استفاده
- `technical_details` (text, nullable) - جزئیات فنی

### 2. Migration: جدول pivot برای ربات‌های مرتبط

فایل: `database/migrations/YYYY_MM_DD_HHMMSS_create_webhook_endpoint_related_bots_table.php`

جدول `webhook_endpoint_related_bots`:

- `id` (bigint, primary)
- `webhook_endpoint_id` (bigint, foreign key)
- `related_webhook_endpoint_id` (bigint, foreign key)
- `order` (integer, default 0) - ترتیب نمایش
- `created_at`, `updated_at`

## به‌روزرسانی Model

### WebhookEndpoint Model

فایل: `app/Models/WebhookEndpoint.php`

اضافه کردن:

- فیلدهای جدید به `$fillable`
- Cast برای `features` به array
- Relationship: `relatedBots()` - belongsToMany
- Relationship: `relatedToBots()` - belongsToMany (reverse)
- Method: `getImageUrlAttribute()` - برای برگرداندن image_url یا image_path

## به‌روزرسانی Nova Resource

### WebhookEndpoint Nova Resource

فایل: `app/Nova/WebhookEndpoint.php`

اضافه کردن فیلدهای جدید:

- `Textarea::make('Detailed Description', 'detailed_description')`
- `Image::make('Image', 'image_path')` - برای آپلود عکس
- `Text::make('Image URL', 'image_url')` - برای URL خارجی
- `KeyValue::make('Features', 'features')` - برای لیست ویژگی‌ها
- `Textarea::make('Usage Instructions', 'usage_instructions')`
- `Textarea::make('Technical Details', 'technical_details')`
- `BelongsToMany::make('Related Bots', 'relatedBots', WebhookEndpoint::class)` - برای انتخاب ربات‌های مرتبط

## Controller

### WelcomeController

فایل: `app/Http/Controllers/WelcomeController.php`

اضافه کردن متد جدید:

- `show(string $endpointId)` - نمایش صفحه جزئیات ربات
  - دریافت ربات از endpoint_id
  - دریافت 3 ربات مرتبط (با ترتیب order)
  - دریافت لیست ویژگی‌ها
  - برگرداندن view با داده‌ها

## Routes

### web.php

فایل: `routes/web.php`

اضافه کردن route:

```php
Route::get('/bot/{endpointId}', [WelcomeController::class, 'show'])
    ->name('bot.show');
```

## Views

### 1. صفحه جزئیات ربات

فایل: `resources/views/bot/show.blade.php`

ویژگی‌ها:

- Header با نام و آیکون ربات
- نمایش عکس (image_url یا image_path)
- توضیحات کوتاه (description)
- توضیحات کامل (detailed_description)
- لیست ویژگی‌ها (features)
- دستورالعمل استفاده (usage_instructions)
- جزئیات فنی (technical_details)
- لینک‌های نمونه (Telegram, Bale)
- بخش ربات‌های مرتبط (3 ربات با کارت‌های زیبا)
- دکمه بازگشت به صفحه اصلی
- طراحی Responsive با Tailwind CSS
- پشتیبانی از Dark Mode

### 2. به‌روزرسانی صفحه اصلی

فایل: `resources/views/welcome.blade.php`

تغییر لینک کارت‌های ربات:

- به جای لینک مستقیم به Telegram/Bale، لینک به صفحه جزئیات (`route('bot.show', $bot->endpoint_id)`)

## Helper Methods

### WebhookEndpoint Model

اضافه کردن متدهای کمکی:

- `getRelatedBots(int $limit = 3)` - دریافت ربات‌های مرتبط با محدودیت
- `getImageAttribute()` - برگرداندن URL عکس (اولویت با image_url، سپس image_path)

## Seeder برای داده‌های اولیه

### BotDetailsSeeder

فایل: `database/seeders/BotDetailsSeeder.php`

این seeder:

- برای هر ربات موجود، توضیحات کامل اضافه می‌کند
- ویژگی‌های اصلی را اضافه می‌کند
- ربات‌های مرتبط را تنظیم می‌کند (بر اساس دسته‌بندی منطقی)

مثال دسته‌بندی ربات‌های مرتبط:

- ربات‌های مذهبی: قرآن، حدیث، نهج البلاغه، نماز قضا
- ربات‌های مدیریتی: ماموریت، مدیا ماموریت، تایید وظایف
- ربات‌های محتوایی: وبلاگ، RSS Feed، پرزنتر
- ربات‌های کاربردی: آب و هوا، Get Chat ID، تست روانشناسی

## نکات مهم

- عکس‌ها در `storage/app/public/bots/` ذخیره می‌شوند
- از `php artisan storage:link` برای لینک کردن storage استفاده شود
- ربات‌های مرتبط به صورت خودکار بر اساس دسته‌بندی انتخاب می‌شوند
- در صورت نبودن عکس، از آیکون SVG یا Emoji استفاده می‌شود
- طراحی باید Responsive و Mobile-Friendly باشد
