# پیاده‌سازی سیستم مدیریت ماموریت‌ها (Missions)

## ساختار کلی

سیستم Missions به صورت جداگانه از Tasks عمل می‌کند. هر Mission می‌تواند به یک Prompt و یک یا چند Content متصل باشد. پرسنل می‌توانند Mission درخواست کنند (رندوم یا ترتیبی) و هر پرسنل فقط یک Mission فعال می‌تواند داشته باشد.

## جداول دیتابیس

### 1. جدول `missions`

- `id`: شناسه یکتا
- `tenant_id`: شناسه تننت
- `title`: عنوان ماموریت
- `description`: توضیحات ماموریت
- `prompt_id`: شناسه پرامپت مرتبط
- `content_id`: شناسه کانتنت اصلی (اختیاری)
- `points`: امتیاز ماموریت
- `max_personnel`: حداکثر تعداد پرسنل برای این ماموریت
- `current_personnel_count`: تعداد فعلی پرسنل اختصاص یافته
- `status`: وضعیت ماموریت (active, inactive)
- `created_at`, `updated_at`

### 2. جدول `contents`

- `id`: شناسه یکتا
- `tenant_id`: شناسه تننت
- `title`: عنوان محتوا
- `content_type`: نوع محتوا (text, video, image, audio, pdf)
- `content_url`: آدرس محتوا
- `description`: توضیحات
- `sort_order`: ترتیب نمایش
- `created_at`, `updated_at`

### 3. جدول `mission_contents` (Pivot)

- `id`: شناسه یکتا
- `mission_id`: شناسه ماموریت
- `content_id`: شناسه محتوا
- `sort_order`: ترتیب ارسال
- `created_at`, `updated_at`

### 4. جدول `mission_personnel` (Pivot)

- `id`: شناسه یکتا
- `mission_id`: شناسه ماموریت
- `personnel_id`: شناسه پرسنل
- `status`: وضعیت (reserved, in_progress, pending_approval, approved, rejected, cancelled)
- `result_link`: لینک نتیجه کار
- `approval_message_id`: شناسه پیام در گروه تایید
- `rejection_reason`: دلیل رد
- `approved_by_chat_id`: شناسه تاییدکننده
- `approved_at`: زمان تایید
- `rejected_at`: زمان رد
- `started_at`: زمان شروع
- `completed_at`: زمان تکمیل
- `created_at`, `updated_at`

### 5. به‌روزرسانی جدول `prompts`

- اضافه کردن `tenant_id`
- اضافه کردن `mission_id` (nullable)
- حفظ `task_id` برای سازگاری با سیستم موجود

## Models

### 1. Mission Model

- Relationships: `tenant()`, `prompt()`, `content()`, `contents()`, `personnel()`
- Scopes: `active()`, `available()`

### 2. Content Model

- Relationships: `tenant()`, `missions()`

### 3. MissionContent Model (Pivot)

- Relationships: `mission()`, `content()`

### 4. MissionPersonnel Model (Pivot)

- Relationships: `mission()`, `personnel()`
- Methods: `approve()`, `reject()`, `cancel()`

### 5. به‌روزرسانی Prompt Model

- اضافه کردن relationship به `mission()`

## Controllers

### 1. MissionController

- `index()`: لیست ماموریت‌های موجود
- `show($id)`: جزئیات یک ماموریت
- `request()`: درخواست ماموریت توسط پرسنل
- `cancel()`: کنسل کردن ماموریت
- `submitResult()`: ارسال لینک نتیجه

### 2. به‌روزرسانی MissionBotController

- `handleRequestMission()`: مدیریت درخواست ماموریت در ربات
- `handleCancelMission()`: مدیریت کنسل ماموریت
- `handleGetTraining()`: دریافت آموزش‌های ماموریت
- `handleSubmitLink()`: ارسال لینک نتیجه (به‌روزرسانی)

### 3. MissionMediaBotController (جدید)

- `handleUploadMedia()`: آپلود مدیا برای یک ماموریت (توسط ادمین)
- `handleGetTraining()`: دریافت آموزش‌های یک ماموریت

## Jobs

### SendMissionMediaJob

- ارسال مدیاهای آموزشی یک ماموریت به ترتیب به پرسنل
- استفاده از Queue برای ارسال ترتیبی
- پشتیبانی از انواع مدیا (video, image, audio, pdf, text)

## Seeders

### 1. PromptSeeder

- ایجاد 10 پرامپت نمونه برای tenant_id = 1
- پرامپت‌ها باید قابل استفاده مجدد باشند

### 2. ContentSeeder

- ایجاد 10 کانتنت نمونه برای tenant_id = 1
- انواع مختلف: video, image, audio, pdf, text

## Routes

### API Routes (`routes/api.php`)

- `GET /api/missions` - لیست ماموریت‌های موجود
- `GET /api/missions/{id}` - جزئیات ماموریت
- `POST /api/missions/{id}/request` - درخواست ماموریت
- `POST /api/missions/{id}/cancel` - کنسل ماموریت
- `POST /api/missions/{id}/submit` - ارسال نتیجه

### Webhook Routes (`routes/web.php`)

- `POST /webhook-mission` - وب‌هوک ربات ماموریت (به‌روزرسانی)
- `POST /webhook-mission-media` - وب‌هوک ربات مدیا ماموریت (جدید)

## AppServiceProvider

- Bind کردن Repository و Service interfaces به implementations

## ویژگی‌های کلیدی

1. **درخواست ماموریت**: پرسنل می‌توانند از بین ماموریت‌های موجود یکی را انتخاب کنند (رندوم یا ترتیبی)
2. **محدودیت یک ماموریت فعال**: هر پرسنل فقط یک ماموریت فعال می‌تواند داشته باشد
3. **ارسال آموزش‌ها**: مدیاهای آموزشی به ترتیب به پرسنل ارسال می‌شوند
4. **فرآیند تایید/رد**: مشابه سیستم Tasks موجود
5. **امتیازدهی**: بعد از تایید، امتیاز به پرسنل اضافه می‌شود
