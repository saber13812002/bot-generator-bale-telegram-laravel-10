# ایجاد صفحه گزارش وب برای نماز قضا

## اهداف

1. ایجاد صفحه گزارش وب با نمودارهای تعاملی برای هر کاربر
2. استفاده از token منحصر به فرد برای دسترسی امن
3. به‌روزرسانی صفحه اصلی bots.pardisania.ir
4. اضافه کردن لینک گزارش به ایمیل‌های هفتگی

## مراحل پیاده‌سازی

### 1. Migration و Model

- **Migration**: اضافه کردن فیلد `web_report_token` به جدول `bot_users`
  - فایل: `database/migrations/YYYY_MM_DD_add_web_report_token_to_bot_users_table.php`
  - فیلد: `string('web_report_token', 64)->nullable()->unique()->after('email_unsubscribe_token')`
  - Index: `$table->index('web_report_token');`
- **Model**: به‌روزرسانی `app/Models/BotUsers.php` برای cast کردن `web_report_token`

### 2. Controller

- **Controller جدید**: `app/Http/Controllers/PrayerReportWebController.php`
  - متد `show(string $token)`: نمایش صفحه گزارش با token
  - متد `test()`: صفحه تست JavaScript
  - دریافت داده‌های گزارش از `PrayerBotService::getWeeklyReport()`
  - تبدیل داده‌ها با `transformReportData()`
  - ارسال به view

### 3. Routes

- **Route در `routes/web.php`**:
  - `Route::get('/نماز-قضا/{token}', [PrayerReportWebController::class, 'show']);`
  - `Route::get('/test-js', [PrayerReportWebController::class, 'test']);`

### 4. Views

- **View اصلی**: `resources/views/prayer-report-web.blade.php`
  - استفاده از Chart.js برای نمودارها
  - نمایش آمار 7 روز گذشته
  - مقایسه با هفته‌های گذشته
  - اطلاعات پیک فعالیت
  - آمار Top 10
  - پیام انگیزشی
  - طراحی Responsive و RTL
- **View تست**: `resources/views/test-js.blade.php`
  - تست لود شدن Chart.js
  - تست نمایش نمودار ساده

### 5. به‌روزرسانی Welcome Page

- **فایل**: `resources/views/welcome.blade.php`
  - اضافه کردن بخش "نماز قضا" به لیست ربات‌ها
  - به‌روزرسانی لیست ربات‌های موجود
  - استفاده از داده‌های دیتابیس برای نمایش ربات‌های فعال (اختیاری)

### 6. تولید و مدیریت Token

- **در `PrayerBotController`**: هنگام تایید ایمیل، تولید `web_report_token` اگر وجود نداشته باشد
  - فایل: `app/Http/Controllers/PrayerBotController.php`
  - متد: `handleEmailVerificationCode()`
  - کد: `$botUser->web_report_token = bin2hex(random_bytes(32));`
- **در `SendPrayerWeeklyReports`**: اطمینان از وجود token برای همه کاربران

### 7. به‌روزرسانی ایمیل‌ها

- **View های ایمیل**: اضافه کردن باکس HTML زیبا با لینک به صفحه گزارش
  - فایل‌ها: `resources/views/emails/prayer-weekly-report-v*.blade.php`
  - باکس با طراحی جذاب و رنگ‌بندی مناسب
  - متن: "برای مشاهده گزارش کامل و نمودارهای تعاملی، اینجا کلیک کنید"
  - لینک: `url('/نماز-قضا/' . $user->web_report_token)`
- **EmailData**: اضافه کردن `reportUrl` به `generateTextReport()`

### 8. به‌روزرسانی transformReportData

- **در Commands**: اضافه کردن `report_url` به `reportData`
  - فایل‌ها: 
    - `app/Console/Commands/SendPrayerWeeklyReports.php`
    - `app/Console/Commands/TestWeeklyReportJob.php`
    - `app/Console/Commands/SendUserWeeklyReport.php`

## نکات امنیتی

- Token باید 64 کاراکتر hex باشد
- Token باید unique باشد
- صفحه گزارش فقط با token قابل دسترسی است (بدون نیاز به لاگین)
- در صورت عدم وجود token یا کاربر، صفحه 404 نمایش داده شود

## تست

1. تست صفحه `/test-js` برای اطمینان از لود شدن JavaScript
2. تست تولید token برای کاربر جدید
3. تست دسترسی به صفحه گزارش با token معتبر
4. تست دسترسی با token نامعتبر (باید 404 شود)
5. تست نمایش نمودارها و داده‌ها
6. تست لینک در ایمیل
