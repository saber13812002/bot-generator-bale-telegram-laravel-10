# طرح: فرکانس متغیر ادمین کانال روزانه + ربات ادمین کانال با صف رسانه پویا

## بخش ۱: فرکانس و زمان‌بندی برای ربات تک‌آیه/حدیث/نهج/شراب

### وضعیت فعلی

- یک Command: [PostDailyVerseToChannels](app/Console/Commands/PostDailyVerseToChannels.php) که همه configهای فعال را یک‌جا پردازش می‌کند.
- در [Kernel.php](app/Console/Kernel.php) فقط یک بار در روز ساعت ۰۹:۰۰ اجرا می‌شود.
- مدل [AdminDailyChannelConfig](app/Models/AdminDailyChannelConfig.php): هیچ فیلدی برای تعداد ارسال در روز یا بازه زمانی ندارد.

### تغییرات پیشنهادی

**۱.۱ جدول `admin_daily_channel_configs`**

- فیلد جدید `posts_per_day`: مقدار فقط ۱، ۲ یا ۴ (پیش‌فرض ۱).
  - ۱ = یک بار در روز (مثلاً ۰۹:۰۰)
  - ۲ = دو بار در روز (مثلاً ۰۹:۰۰ و ۲۱:۰۰، فاصله ۱۲ ساعت)
  - ۴ = چهار بار در روز (مثلاً ۰۶:۰۰، ۱۲:۰۰، ۱۸:۰۰، ۰۰:۰۰، فاصله ۶ ساعت)
- کوئری دستی برای MSSQL (در صورت عدم استفاده از migrate) در README یا کامنت مایگریشن درج شود.

**۱.۲ زمان‌بندی در Kernel**

- به‌جای یک بار در روز، Command در **اسلات‌های ثابت** اجرا شود تا هر config بر اساس `posts_per_day` خودش در نوبت مناسب ارسال کند.
- پیشنهاد اسلات‌ها (بر اساس ساعت ایران یا UTC طبق تنظیم پروژه):
  - اسلات ۱: مثلاً ۰۰:۰۰ (نیم‌شب)
  - اسلات ۲: ۰۶:۰۰
  - اسلات ۳: ۱۲:۰۰
  - اسلات ۴: ۱۸:۰۰
- یعنی چهار بار در روز `daily-channel:post` اجرا شود (مثلاً `->dailyAt('00:00')`, `->dailyAt('06:00')`, ...).

**۱.۳ منطق داخل Command**

- به Command آرگومان یا گزینه `--slot` پاس داده شود (۱ تا ۴) تا بداند الان کدام اسلات است؛ یا داخل Command از ساعت فعلی اسلات را محاسبه کند (مثلاً slot = (hour/6) % 4 + 1).
- برای هر config:
  - اگر `posts_per_day == 1`: فقط در یک اسلات ثابت (مثلاً اسلات ۲ = ۰۶:۰۰) ارسال شود.
  - اگر `posts_per_day == 2`: در دو اسلات (مثلاً ۱ و ۳ یا ۲ و ۴).
  - اگر `posts_per_day == 4`: در هر چهار اسلات.
- نتیجه: هر config فقط در اسلات‌های مجاز خودش محتوا دریافت می‌کند؛ بقیه نوبت‌ها برای آن config اجرا نمی‌شود.

**۱.۴ ربات مادر (ویزارد)**

- در جریان فعلی ادمین کانال روزانه، بعد از انتخاب نوع محتوا (آیه/حدیث/نهج/شراب/ترکیبی/ترتیبی) یک مرحله اضافه شود: «تعداد ارسال در روز: ۱ = یک بار، ۲ = دو بار، ۴ = چهار بار» (فقط این سه گزینه). مقدار در `posts_per_day` ذخیره شود.
- در حالت «ویرایش» یا «تکمیل تنظیمات» هم امکان تغییر `posts_per_day` باشد (مثلاً از همان منوی ویرایش یا مرحله جدا).

## بخش ۲: ربات جدید «ادمین کانال با صف رسانه پویا»

### مفهوم

- یک **endpoint جدید** در ربات مادر با نام «ادمین کانال با صف رسانه پویا».
- منبع محتوا دیگر فقط آیه/حدیث/نهج/شراب نیست؛ بلکه **صف مطالب** (صف رسانه) است: لیست مرتبی از آیتم‌ها (متن، عکس، ویدیو و در صورت نیاز سرفصل/عنوان).
- ادمین در ویزارد ربات مادر: ابتدا **صف** را می‌سازد (نام صف + افزودن آیتم‌ها یکی‌یکی)، سپس همانند ادمین کانال روزانه **کانال/گروه/خصوصی** بله، تلگرام و ایتا را وصل می‌کند.
- ارسال به‌صورت نوبتی از صف (مثلاً هر بار آیتم بعدی، بعد از آخرین آیتم دوباره از اول).

### مدل داده

**۲.۱ جدول `media_queues` (صف‌های رسانه)**

- `id`, `admin_chat_id` (مالک صف)، `name` (نام صف، مثلاً «مناسبت‌ها»), `created_at`, `updated_at`.

**۲.۲ جدول `media_queue_items` (آیتم‌های هر صف)**

- `id`, `media_queue_id`, `position` (ترتیب نمایش، integer).
- `content_type`: مثلاً `text`, `photo`, `video` (در صورت نیاز بعداً `document` و غیره).
- `content_text` / `caption`: متن همراه آیتم.
- `file_id_telegram`, `file_id_bale`: شناسه فایل در API تلگرام/بله (هر پلتفرم file_id خودش را دارد؛ اگر آیتم از تلگرام اضافه شده فقط `file_id_telegram` پر می‌شود و برای بله در ارسال فقط caption یا متن فرستاده می‌شود و برعکس).
- `created_at`, `updated_at`.

**نکته:** اگر ویزارد فقط از یک پلتفرم (مثلاً تلگرام) برای «افزودن عکس/ویدیو» استفاده شود، فقط `file_id` همان پلتفرم پر می‌شود؛ در ارسال به پلتفرم دیگر فقط متن/caption ارسال شود (یا در ویزارد ذکر شود که عکس/ویدیو فقط برای همان پلتفرم است).

### ویزارد در ربات مادر

**۲.۳ Endpoint و جریان کلی**

- در [ImportWebhookEndpointsDefault](app/Console/Commands/ImportWebhookEndpointsDefault.php) (یا سیدر مربوطه) یک endpoint جدید با id مثلاً `admin-channel-media-queue` و نام «ادمین کانال با صف رسانه پویا» اضافه شود.
- انتخاب پلتفرم (تلگرام/بله) مثل ادمین کانال روزانه؛ سپس:
  1. **انتخاب یا ساخت صف:** لیست صف‌های قبلی این ادمین (با نام) + گزینه «صف جدید». در صورت جدید: درخواست نام صف.
  2. **مدیریت آیتم‌های صف:** برای صف انتخاب‌شده: «آیتم بعدی را بفرست (متن، عکس یا ویدیو) یا /done برای پایان.» هر پیام متن = یک آیتم text؛ هر عکس = یک آیتم photo؛ هر ویدیو = یک آیتم video. با /done به مرحله بعد برو.
  3. **اتصال کانال‌ها:** دقیقاً مثل ادمین کانال روزانه با استفاده از [MultiPlatformChannelWizardHelper](app/Helpers/MultiPlatformChannelWizardHelper.php): بله (فوروارد یا چت‌آیدی)، تلگرام (فوروارد یا چت‌آیدی)، ایتا (شناسه).
- ذخیره در جدول **جدید** مثلاً `admin_channel_media_queue_configs`: `admin_chat_id`, `media_queue_id`, `bale_channel_chat_id`, `telegram_channel_chat_id`, `eitaa_channel_chat_id`, `is_active`, و در صورت نیاز `last_sent_item_index` برای نوبت‌دهی.

### ارسال از صف

**۲.۴ Command و زمان‌بندی**

- یک Command جدید مثلاً `PostMediaQueueToChannels` (یا گسترش همان `PostDailyVerseToChannels` با نوع محتوا «queue» و جدول جدا).
- این Command فقط configهای مربوط به «ادمین کانال با صف رسانه» را می‌خواند؛ برای هر config آیتم بعدی صف را (بر اساس `last_sent_item_index`) انتخاب می‌کند؛ متن را با `sendMessage` و عکس/ویدیو را با `sendPhoto`/`sendVideo` (مشابه [ContentSubmissionServiceImpl](app/Services/ContentSubmissionServiceImpl.php) خطوط ۲۵۲–۲۶۹) به هر کانال/گروهی که پر شده ارسال می‌کند؛ سپس `last_sent_item_index` را به‌روز می‌کند (و بعد از آخرین آیتم به ۰ یا به ترتیب دور).
- زمان‌بندی این Command در Kernel: می‌توان همان اسلات‌های ۱/۲/۳/۴ (یا فقط یک بار در روز) در نظر گرفت؛ یا در config این ربات هم فیلد `posts_per_day` داشته باشد تا با همان منطق اسلات‌ها هماهنگ شود.

### استفاده در «ربات‌های دیگر»

- ماژول «جمع‌آوری کانال/گروه برای چند پلتفرم» از قبل با `MultiPlatformChannelWizardHelper` قابل استفاده مجدد است.
- ربات جدید «ادمین کانال با صف رسانه» خودش یک endpoint جدا است؛ هر ربات دیگری که در آینده بخواهد «از یک صف محتوا به کانال بفرستد» می‌تواند از همان مدل `media_queues` و `media_queue_items` و همین ویزارد/Command استفاده کند یا به این endpoint ارجاع داده شود. تفاوت فقط در منبع محتوا (صف به‌جای آیه/حدیث/نهج/شراب) و جدول config (`admin_channel_media_queue_configs`) است.

## خلاصه فایل‌ها و دیتابیس


| مورد      | فایل / جدول                                                                                                                              |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| فرکانس    | مایگریشن اضافه کردن `posts_per_day` به `admin_daily_channel_configs`؛ مدل، Command، Kernel، ویزارد BotMother                             |
| صف رسانه  | مایگریشن `media_queues` و `media_queue_items`؛ مدل‌های MediaQueue و MediaQueueItem؛ مایگریشن و مدل `admin_channel_media_queue_configs`   |

| زمان‌بندی | Kernel: اجرای daily-channel در ۴ اسلات؛ Command جدید صف در اسلات(ها) یا روزانه                                                           |
