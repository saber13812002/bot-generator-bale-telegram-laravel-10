# سیستم مدیریت فایل‌های آپلود شده برای ربات‌ها

## هدف

پیاده‌سازی سیستم مدیریت فایل‌های آپلود شده برای جلوگیری از آپلود مجدد فایل‌های یکسان در ربات‌های تلگرام و بله. هر ربات فقط به فایل‌های خودش دسترسی دارد، بنابراین باید file_id برای هر ربات به صورت جداگانه نگهداری شود.

## معماری

### 1. جدول جدید: `bot_uploaded_files`

جدول برای نگهداری file_id های آپلود شده توسط هر ربات:

```sql
- id (bigint, primary key)
- bot_id (bigint, foreign key -> bots.id)
- bot_type (enum: 'telegram', 'bale')
- file_unique_key (string, unique) - کلید یونیک برای شناسایی فایل
- file_type (enum: 'scan_page', 'audio_recitation', 'audio_translation', 'audio_page', 'photo', 'document', 'video', 'audio')
- file_id (string) - file_id برگشتی از تلگرام/بله
- file_unique_id (string, nullable) - file_unique_id از API
- file_size (integer, nullable)
- width (integer, nullable) - برای عکس
- height (integer, nullable) - برای عکس
- metadata (json, nullable) - اطلاعات اضافی (مثلاً sura, aya, page, hr, reciter, cdn)
- upload_response (json, nullable) - پاسخ کامل API آپلود
- created_at, updated_at
```

**Indexes:**

- `(bot_id, bot_type, file_unique_key)` - unique
- `(file_unique_key)` - index
- `(bot_id, bot_type, file_type)` - index

### 2. ساختار file_unique_key

کلید یونیک برای هر نوع فایل:

- **اسکن صفحه قرآن:**
  - Format: `scan_page_{hr}_{page}_{bot_type}`
  - Example: `scan_page_1_1_telegram`, `scan_page_2_604_bale`

- **فایل صوتی قرائت:**
  - Format: `audio_recitation_{reciter}_{sura}_{aya}_{bot_type}`
  - Example: `audio_recitation_parhizgar_1_1_telegram`

- **فایل صوتی ترجمه:**
  - Format: `audio_translation_{locale}_{sura}_{aya}_{bot_type}`
  - Example: `audio_translation_fa.makarem_1_1_bale`

- **فایل صوتی صفحه:**
  - Format: `audio_page_{page}_{bot_type}`
  - Example: `audio_page_1_telegram`

### 3. Helper جدید: `FileUploadHelper`

کلاس Helper برای مدیریت فایل‌های آپلود شده:

**متدها:**

- `getOrUploadFile($bot, $fileUniqueKey, $fileUrl, $fileType, $metadata = [])` - چک می‌کند آیا فایل قبلاً آپلود شده یا نه
- `saveUploadedFile($bot, $fileUniqueKey, $fileType, $response, $metadata = [])` - ذخیره file_id در دیتابیس
- `getFileId($botId, $botType, $fileUniqueKey)` - دریافت file_id از دیتابیس
- `generateFileUniqueKey($fileType, $params, $botType)` - ساخت کلید یونیک

### 4. تغییرات در Helper های موجود

**`QuranHelper.php`:**

- `sendScanPage()` - استفاده از `FileUploadHelper` برای چک کردن file_id
- `sendAudio()` - استفاده از `FileUploadHelper` برای فایل‌های صوتی
- `sendAudioByLocale()` - استفاده از `FileUploadHelper`
- `sendAudioMp3Page()` - استفاده از `FileUploadHelper`

**`BotHelper.php`:**

- `sendPhoto()` - استفاده از `FileUploadHelper` برای عکس‌ها
- `sendAudio()` - استفاده از `FileUploadHelper` برای فایل‌های صوتی

**`QuranWordController.php`:**

- `saveToQuranScanPagesTable()` - تغییر برای استفاده از جدول جدید
- استفاده از `FileUploadHelper` در تمام نقاط ارسال فایل

### 5. Background Job: `PreUploadQuranFilesJob`

Job برای پیش‌آپلود فایل‌های قرآن:

**عملکرد:**

1. دریافت لیست ربات‌ها از دیتابیس
2. برای هر ربات:

   - اسکن صفحات (604 صفحه × 4 CDN = 2416 فایل)
   - فایل‌های صوتی قرائت (6236 آیه × تعداد reciter ها)
   - فایل‌های صوتی صفحه (604 صفحه)

3. دانلود از CDN
4. آپلود به تلگرام/بله
5. ذخیره file_id در دیتابیس
6. پاک کردن فایل موقت

**Command:** `php artisan quran:pre-upload-files [--bot-id=] [--type=] [--limit=]`

## نکات مهم

1. **یونیک بودن file_unique_key:** باید برای هر ربات و نوع فایل یونیک باشد
2. **مدیریت خطا:** در صورت خطا در آپلود، باید لاگ شود و ادامه دهد
3. **Rate Limiting:** برای جلوگیری از محدودیت API، باید delay بین آپلودها باشد
4. **پاک کردن فایل‌های موقت:** بعد از آپلود، فایل‌های دانلود شده باید پاک شوند
5. **Fallback:** در صورت عدم وجود file_id در دیتابیس، باید فایل آپلود شود
