# پیاده‌سازی ربات پرزنتر (Presenter Bot)

## خلاصه

ربات پرزنتر رباتی است که متن‌های آماده را به ترتیب خط به خط برای کاربران ارسال می‌کند. کاربر با /start شروع می‌کند و با دکمه "بعدی" به خط بعدی می‌رود.

## معماری

### 1. دیتابیس

#### جدول `presenter_bots`

- `id`: شناسه ربات
- `bot_id`: ارتباط با جدول `bots` (foreign key)
- `content`: متن کامل (هر خط با `\n` جدا می‌شود)
- `created_at`, `updated_at`

#### Migration

```php
Schema::create('presenter_bots', function (Blueprint $table) {
    $table->id();
    $table->unsignedBigInteger('bot_id')->unique();
    $table->text('content'); // متن کامل با خطوط جدا شده با \n
    $table->timestamps();
    
    $table->foreign('bot_id')->references('id')->on('bots')->onDelete('cascade');
});
```

### 2. ساخت ربات از بات مادر

#### 2.1 اضافه کردن Endpoint

در `app/Helpers/WebhookEndpointHelper.php`:

- اضافه کردن endpoint جدید `webhook-presenter-bot` به لیست endpoints

#### 2.2 State Management

در `app/Helpers/BotMotherStateHelper.php`:

- اضافه کردن state جدید: `STATE_WAITING_PRESENTER_CONTENT` برای دریافت محتوای ربات

#### 2.3 منطق ساخت ربات

در `app/Http/Controllers/BotMotherController.php`:

- بعد از دریافت توکن، اگر endpoint `webhook-presenter-bot` باشد:

  1. درخواست ارسال محتوا (متن‌ها)
  2. دریافت محتوا (هر خط یک پیام)
  3. ذخیره محتوا در جدول `presenter_bots`
  4. ساخت ربات و تنظیم webhook

### 3. Controller ربات پرزنتر

#### فایل: `app/Http/Controllers/PresenterBotController.php`

- Handle webhook ربات پرزنتر
- مدیریت state کاربر (کدام خط را دیده است)
- ارسال خط بعدی با دکمه "بعدی"
- مدیریت callback query برای دکمه "بعدی"

### 4. State Management برای کاربران

#### استفاده از `BotUsers` model

- استفاده از متد `setting()` برای ذخیره state کاربر
- `current_line`: شماره خط فعلی که کاربر باید ببیند
- `total_lines`: تعداد کل خطوط

### 5. Route

در `routes/api.php`:

```php
Route::post('/webhook-presenter-bot', [PresenterBotController::class, 'index']);
```

### 6. Model

فایل: `app/Models/PresenterBot.php`

- Relationship با `Bot`
- متد برای دریافت خطوط (با حذف خطوط خالی)

## جریان کار

### ساخت ربات:

1. کاربر در بات مادر `/start` می‌زند
2. Endpoint را انتخاب می‌کند (ربات پرزنتر)
3. نوع ربات را انتخاب می‌کند (Telegram/Bale)
4. زبان را انتخاب می‌کند (در صورت نیاز)
5. توکن را ارسال می‌کند
6. محتوای ربات را ارسال می‌کند (هر خط یک پیام)
7. ربات ساخته می‌شود و webhook تنظیم می‌شود

### استفاده از ربات:

1. کاربر `/start` می‌زند
2. ربات خط اول را ارسال می‌کند + دکمه "بعدی"
3. کاربر روی "بعدی" کلیک می‌کند
4. ربات خط بعدی را ارسال می‌کند + دکمه "بعدی"
5. این روند تا آخرین خط ادامه می‌یابد
6. در آخرین خط، پیام "پایان معرفی" نمایش داده می‌شود

## نکات پیاده‌سازی

1. **حذف خطوط خالی**: قبل از ذخیره، خطوط خالی از محتوا حذف می‌شوند
2. **State Management**: از `BotUsers::setting()` برای ذخیره state استفاده می‌شود
3. **Inline Keyboard**: از inline keyboard برای دکمه "بعدی" استفاده می‌شود
4. **Callback Query**: مدیریت کلیک روی دکمه "بعدی" با callback query
5. **Webhook Verification**: بعد از ساخت ربات، webhook را verify می‌کنیم

## تست

1. ساخت ربات از بات مادر
2. ارسال محتوا (چند خط متن)
3. تست `/start` در ربات جدید
4. تست دکمه "بعدی"
5. تست پایان معرفی
