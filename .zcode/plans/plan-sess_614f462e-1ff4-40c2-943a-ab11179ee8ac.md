# API با توکن — سخت‌سازی امنیتی + پر کردن گپ‌ها

## واقعیت فعلی

این تسک (بخش ۴ `REMAINING_TASKS.md`) **تقریباً قبلاً ساخته شده** — مدل `ApiToken` (hash sha256، نوع `tenant`/`super_admin`، `tenant_id`)، middleware `api.token` (alias در `Kernel.php:69`)، `MissionApiController` با endpointهای `v1/missions`، و مستندات کامل در `docs/API_README.md` موجوده. پس کار سبز نیست؛ بیشتر **سخت‌سازی امنیتی + پر کردن گپ‌ها** هست.

## گپ‌ها و تغییرات

### ۱. باگ امنیتی — اسکوپ‌تننتی از input کلاینت (مهم)

`MissionApiController` در ۶ جا (`createMission:53,104`؛ `addContent:188-189`؛ `listMissions:243`؛ `getMission:278-279`؛ `getMissionStatus:403-404`؛ `assignMission:476-477`) از `$request->input('is_super_admin')` و `$request->input('tenant_id')` قرائت می‌کنه — یعنی **کلاینت** می‌تونه `is_super_admin=true` بفرسته و به همه تننت‌ها دسترسی بگیره.

**تغییر:** helper خصوصی اضافه می‌کنم:
```php
private function effectiveTenantId(Request $request): ?int
{
    $token = $request->api_token;
    if ($token->type === 'super_admin') {
        // super-admin: tenant_id از body (اختیاری) یا همه تننت‌ها
        return $request->input('tenant_id'); // null = همه
    }
    return $token->tenant_id; // tenant token: همیشه از توکن
}
```
و یه guard مشترک برای دسترسی:
```php
private function assertTenantAccess(Request $request, int $missionTenantId): ?string // null = ok, string = error
{
    $token = $request->api_token;
    if ($token->type === 'super_admin') return null; // access all
    if ((int)$token->tenant_id !== (int)$missionTenantId) return 'Access denied';
    return null;
}
```
همه‌ی `$request->input('is_super_admin')` و fallback‌های `$request->input('tenant_id') ?? $request->api_token->tenant_id` جایگزین می‌شن با قرائت از `$request->api_token->type` / `->tenant_id`.

### ۲. `POST /api-tokens/generate` super-admin-only

`ApiTokenController::generateToken` فقط `api.token` guard داره — هر توکن tenant می‌تونه super_admin بسازه.

**تغییر:** اولِ method اضافه می‌کنم:
```php
if ($request->api_token->type !== 'super_admin') {
    return response()->json(['success' => false, 'message' => 'Super admin token required'], 403);
}
```

### ۳. `createMission` از طریق Service/Repository

`createMission` مستقیم `Mission::create()` می‌زنه. `MissionRepository::create(array $data)` موجوده (در `MissionRepositoryImpl:16`).

**تغییر:** `MissionApiController` رو با `MissionRepository` inject می‌کنم (constructor) و `Mission::create([...])` رو با `$this->missionRepository->create([...])` جایگزین می‌کنم. منطق transaction/prompt/content/pivot در controller می‌مونه (چون ترکیبی از ۳ مدله) ولی creation مامیت از repository رد می‌شه.

### ۴. endpointهای کم

- **`POST /v1/missions/{id}/prompt`** → `updatePrompt(Request, $missionId)` — ویرایش prompt موجود (تننتی-scope). `prompt_content` required.
- **`GET /v1/tokens`** → `listTokens(Request)` — لیست توکن‌ها (super_admin: همه؛ tenant: فقط توکن‌های خودش). بدون `plain_token`.
- **`DELETE /v1/tokens/{id}`** → `revokeToken(Request, $tokenId)` — `is_active=false` (soft revoke). super_admin یا owner tenant.

### ۵. Routes (`routes/api.php`)

در گروه `v1/missions` (line 189-197) اضافه:
```php
Route::post('/{id}/prompt', [MissionApiController::class, 'updatePrompt']);
```
گروه جدید `v1/tokens` با `api.token`:
```php
Route::prefix('v1/tokens')->middleware('api.token')->group(function () {
    Route::get('/', [ApiTokenController::class, 'listTokens']);
    Route::delete('/{id}', [ApiTokenController::class, 'revokeToken']);
});
```
